# Established world script provenance check

## Build the provenance list first

- Read the approved series record and the most recent delivered script before you write a new draft.

- List every setting, object, relationship, history detail and motive the new draft will use.

- Write the source beside each item, naming the approved record or the earlier script it came from.

- Mark any item with no source as a proposal, not as established canon.

## Test each new element before it enters the draft

- Ask who placed an object, why it is there and why a character would believe what the draft claims about it.

- Cut an object or action when you cannot answer those questions from an approved source or a flagged proposal.

- Keep a sudden event as a process, naming each step that leads to the fall, the break or the arrival, instead of jumping to the result.

- Keep a character reaction consistent with the state the character is actually in, including where the character is hiding and who the character can speak to.

- Keep a character history consistent with earlier delivered work, including earlier encounters and relationships, instead of resetting a relationship to a convenient starting point.

## Separate proposals from established canon

- Present proposed new elements in a short list before the draft, with one line each on what the element adds.

- Write the draft using only approved elements and proposals the user has accepted.

- Do not grow an approved detail over time, such as a crack, a count or a rule, unless the user approves the growth.

- Do not turn a visual gag or a pleasing image into a motive, a gift or a plan unless its cause is approved.

- When the user rejects a proposal, remove it from the draft and from the provenance list, and do not reintroduce it in a later draft in different words.

## Present the draft with its checks

- Attach the provenance list to the draft or name its location in the reply that carries the draft.

- Name each flagged proposal that the draft uses, so the user can see what still needs approval.

- State plainly when a requested beat cannot be written from approved canon, and offer the missing source as a question instead of filling the gap silently.

## Alternatives for better results

- Ask the user to approve a short proposal list before you write a long draft, when the draft depends on several new elements.

- Reuse a beat from an earlier delivered script when its source is already approved, instead of inventing a parallel beat.

- Split a draft that needs many new elements into a short canon proposal first and a full draft second, so approval comes before writing effort.
