# Script generation density budget

## Count beats before you estimate

- Count the beats in the script or director version before you quote any duration.

- Treat one beat as one generation unit for this workflow.

- Use the measured density from recent work for this workflow, which is one beat holding about 10 to 15 seconds of finished material.

- Count a beat again when it survives a revision and remove it from the count when the user cuts it.

- Do not count a shot, a line, or a segment as a beat unless it is a complete generation unit.

## Compute the floor and report it honestly

- Multiply the beat count by the measured density to get a floor range for total duration.

- Report the floor range as a floor, not as a promised runtime.

- Report the beat count alongside any runtime claim so the reader can check the math.

- Report segment counts only and give no per segment seconds when a segment has no measured duration.

- Refuse to assign seconds to a segment to make a total fit a target length.

## Cut instead of compressing

- Delete redundant beats first when a total is over budget.

- Give a remaining beat the fastest functional treatment that still shows its process.

- Do not claim that merging two segments creates time, because merging does not reduce the generation units the beats need.

- Do not use a jump cut to delete a journey when the journey itself is the drama, because that cut removes the process the audience needs to see.

- Accept the longer floor or ask the user to cut more beats when no honest compression remains.

## Update the density after a new trial

- Replace the density figure after a new measured trial shows a different result.

- Do not keep an old density figure after the generation tool or the workflow changes.

- State the trial that supports the density figure when you report a budget.

## Alternatives for better results

- Present the beat count and floor range for approval before you draft a director version, so the user can cut beats before writing effort grows.

- Keep a beat ledger across revisions so a cut beat does not return silently in a later version.

- Offer the choice between cutting beats and accepting the longer floor in plain terms, instead of inventing a shorter total.
